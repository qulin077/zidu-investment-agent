# 部署与隐私检查

> 状态：公开提交包、独立 GitHub 仓库和可操作 Web Demo 已完成。完整 Runtime 已完成本地冷启动与自动化验收；公开 Web 为使用 Fixture 的评审切片。本文只记录已经检查或已经实现的事项，不以计划冒充结果。

## 1. 为什么不能直接公开当前仓库

当前**本地工作区**首先是产品作者的个人投资环境，不是公开 Demo 数据集。比赛版本以本地现状为源；GitHub 只作为最终发布目标，不反向覆盖或代表本地最新版。2026-10-11 对本地 Git 已跟踪边界做只读审计后发现：

| 风险面 | 已跟踪数量 | 结论 |
|---|---:|---|
| `10-我的交易/**` | 158 | 包含交割单、复盘、持仓、交易记录和对话日记，禁止进入公开仓库 |
| `data/**` | 939 | 包含原始行情、日更派生数据，不能默认视为可公开且会显著增大仓库 |
| 环境变量文件 | 1 | 仅 `.env.example` 被跟踪，字段为空 |
| Token 模式扫描 | 0 个真实凭证 | 两处命中均为环境变量名称或示例，不是实际 Secret |

因此采用“新建干净比赛仓库 + 白名单导出”，而不是在当前 Git 历史上删几个文件后直接公开。后者无法消除历史提交中可能存在的个人数据。

## 2. 隔离方案

比赛版本：

- 产品名：**自渡 ThesisLoop**；
- 仓库名：`zidu-investment-agent`；
- Demo 身份：匿名用户 `demo-investor`；
- Demo 研究：公开来源的东山精密研究；
- Demo 决策与成交：明确标注为模拟数据；
- 构建目录：`submission/ifind-ai-native/build/`，已被当前仓库忽略。

安全导出直接读取本地文件系统，因此会包含白名单内尚未提交的本地代码；是否被 Git 跟踪不决定是否导出。它由以下文件共同控制：

- `export_allowlist.txt`：仅允许复制产品代码、测试、Eval、公开配置和说明；
- `scripts/build_competition_export.py`：再次硬拦截个人目录、运行数据、数据库、凭证和构建缓存；
- 新比赛仓库：从导出结果初始化，绝不继承当前仓库 Git 历史。

## 3. 公开版数据规则

### 可以进入

- 自己编写的源代码、测试和 Eval 定义；
- 公开网页的 URL、标题、发布日期和必要的短摘录；
- 明确允许使用的 iFinD / 公开行情字段及字段说明；
- 匿名且合成的 Decision、Trade、Review 示例；
- BadCase 的脱敏输入、Trace 摘要、根因和修复结果。

### 不得进入

- 真实姓名、账号、持仓、成本、成交、盈亏和私人对话；
- LLM、iFinD、数据库或部署平台的 Token；
- 未获得再分发许可的研报全文、财报 PDF 镜像或付费内容；
- 本机绝对路径、Cookie、请求头和完整第三方响应；
- 模型隐藏思维链。前端只展示可核验的 Action / Observation。

## 4. Secret 与日志原则

- Key 只通过服务端环境变量注入，前端不得出现；
- `.env`、私钥、数据库文件默认忽略；
- 日志只记录工具名、状态、耗时、来源 URL、字段缺口与错误类型；
- HTTP Header、查询 Token、原始用户隐私不得写入 Trace；
- 线上报错对用户显示可理解的降级原因，服务端日志也必须脱敏。
