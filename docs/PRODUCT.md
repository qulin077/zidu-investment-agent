# 自渡 ThesisLoop｜AI Native 个人投资研究与复盘 Agent

> 产品版本：比赛版方案 v1  
> 核心场景：自主投资者围绕一家公司完成“研究 → 决策 → 执行 → 复盘 → 经验沉淀”  
> 风险边界：不荐股、不预测确定性涨跌、不承诺收益、不自动交易

## 1. Executive Summary

个人投资者并不缺新闻、行情或一次性答案，缺的是一条能跨时间保存证据、判断和行动的工作流。

**自渡 ThesisLoop** 是一个面向自主投资者的长期 Investment Agent：用户从自然语言问题出发，Agent 规划并调用行情、财报、公告、网页和已有研究档案，生成带原文依据、冲突和缺口的公司研究；用户确认自己的判断后，系统冻结当时的 Thesis 和约束；成交或新事实出现后，再对照事前判断、实际执行和结果完成复盘，最终由用户确认是否沉淀为个人 Pattern / Rule。

它不是替用户做投资决定，而是让用户自己的研究和复盘变得可追溯、可更新、可复用。

## 2. 目标用户与核心问题

### 目标用户

有两年以上 A 股投资经验、会主动研究公司或产业、使用多个信息源，并愿意记录投资逻辑的个人投资者。

### 核心问题

研究资料、当时的投资判断、实际交易与事后复盘散落在不同工具和时间点：

- 搜索和聊天可以给答案，却不稳定维护同一家公司长期变化；
- 行情软件保存价格和成交，却不知道用户为什么交易；
- 笔记可以保存文字，却不会主动核对新事实、来源和失效条件；
- 普通复盘容易只看盈亏，忽略研究错误与执行错误的区别。

详见 [用户研究与问题证据](./02_用户研究与问题证据.md)。

## 3. 一句话价值和核心任务

### 一句话价值

**把分散信息变成可验证的长期判断，把交易结果变成可复用的个人经验。**

### 唯一核心任务

> 用户选择一家公司，完成一次有来源的研究，确认一条模拟投资决策，并在新事实与模拟成交出现后完成一次结构化复盘。

比赛版不把市场看板、全量行业库或复杂 Memory 管理作为主任务；这些能力存在，但不与核心闭环争夺注意力。

## 4. 产品主链路

### 4.1 用户旅程

| 阶段 | 用户动作 | Agent / 系统动作 | 产物 |
|---|---|---|---|
| 1. 提问 | 在 Agent 输入“完整研究东山精密，重点看 PCB 与光模块业务变化” | 识别公司研究；若范围不清先追问关注周期和方向 | Research Brief |
| 2. 规划 | 查看可核验执行过程 | Planner 拆解财务、业务、管理层、卖方、市场叙事、反证和行情任务 | Research Plan |
| 3. 取证 | 等待或查看来源 | 并行调用公告/财报、行情、iFinD、网页搜索与原文读取；失败则换来源或暴露缺口 | Source + Evidence |
| 4. 综合 | 阅读报告和来源 | 强模型基于证据形成公司基本盘、核心判断、预期差、催化、风险和监控指标 | Dossier / Thesis |
| 5. 决策 | 用自己的话表达计划并确认 | 将研究版本、计划、条件和失效点组成草稿；确认前不写入 | Decision |
| 6. 复盘 | 导入模拟成交并回答逐步问题 | 锁定 Entry Context，对比实际执行、新事实和结果；不替用户归因 | Review |
| 7. 沉淀 | 确认或拒绝 Pattern / Rule | 只有多次证据和用户确认后才进入长期记忆 | Personal Memory |

### 4.2 两分钟 Demo

1. **Agent（0–45 秒）**：输入推荐问题，展示意图澄清、研究计划、工具调用和补搜。
2. **Research（45–85 秒）**：打开公司档案，查看三年财务表、核心 Thesis、市场预期、催化剂、反证、缺口和来源。
3. **Decision（85–105 秒）**：输入模拟计划，展示“解析为草稿 → 用户确认 → 冻结 Entry Context”。
4. **Review（105–120 秒）**：打开预置模拟成交，对照“当时怎么想、实际怎么做、后来发生什么”，确认一条复盘结论。

完整联网研究可能需要数分钟，Demo 使用已生成的公开研究档案；“重新研究”仍可展示真实执行流。

## 5. 信息架构

### 5.1 比赛版主导航

| 一级入口 | 用户问题 | 页面职责 |
|---|---|---|
| Agent | “我现在想做什么？” | 唯一自然语言入口；澄清、规划、执行、记录 |
| Research | “关于这个对象，我们目前知道什么、发生了什么变化？” | 公司 / 行业 / 事件的版本化研究档案 |
| Review | “我当时怎么想、实际怎么做、哪里需要改？” | Decision、Execution、Outcome 对照与归因 |

### 5.2 降级入口

- Market：保留为数据环境与研究更新触发器，不进入比赛主导航；
- Today：并入 Agent 首页的待办摘要，不再与 Review 形成两个相似入口；
- Memory：作为 Review 的二级页面展示 Pattern / Rule，不作为一级导航；
- Frameworks、Chains、Modes、News：保留能力但不作为本次 Demo 入口。

这不是删除原产品能力，而是给评委一个清晰的产品切片。

## 6. 三个核心页面

### 6.1 Agent：任务与执行

首屏只保留：

- 一句话输入；
- 三个可点击示例：完整研究、记录决策、复盘交易；
- 当前执行的可核验 Trace；
- 最近研究和待复盘事项。

Trace 只展示“计划了什么、调用了什么、拿到了什么、还缺什么、为什么停止”，不展示模型隐藏思维链。

### 6.2 Research：长期研究档案

Research 不是第二个聊天框，也不是新闻流。每个研究对象都有一个持续更新的 Dossier：

1. 公司基本盘与商业模式；
2. 三年年报 + 最新季报的财务表；
3. 核心壁垒、增长与利润驱动；
4. 市场预期：公司指引、一致预期、卖方预测、市场叙事；
5. 当前股价与预期的 Gap；
6. 本轮新增事实与 Thesis 变化；
7. 催化剂、风险、反证和失效条件；
8. 下一步监控指标；
9. 来源、冲突、缺口和版本历史。

公司、行业和事件共享证据与时间线，但使用不同的研究模板。

### 6.3 Review：事前与事后对照

Review 第一屏是事实，不是 AI 点评：

- 当时研究版本和市场环境；
- 用户确认的 Thesis、计划、失效点；
- 实际成交、价格路径和结果；
- 复盘时新增事实。

Agent 一次只问一个归因问题，用户确认后再完成 Review。单次复盘不会直接变成规则；Pattern 需要多个相似案例，Rule 需要用户显式激活。

## 7. 产品状态与 Human in the Loop

| 对象 | 状态 | 谁能改变 |
|---|---|---|
| Research | Draft → Partial / Complete → Updated | Coverage Checker 判覆盖；用户可继续研究 |
| Thesis | Proposed → Confirmed → Strengthened / Weakened / Invalidated | 模型提出；关键判断由用户确认 |
| Decision | Draft → Confirmed → Executed / Cancelled | 只有用户确认才能写入 |
| Review | Pending → In Progress → Reviewed | 用户确认结果、违规和归因 |
| Pattern | Candidate → Confirmed / Dismissed | 系统聚类候选；用户确认 |
| Rule | Proposed → Active / Rejected / Retired | 用户显式操作 |

HITL 不是所有步骤都询问用户，而是在**意图改变路径、关键事实冲突、个人判断写入和长期规则写入**四类高影响节点暂停。

## 8. 为什么需要 LLM / Agent

### 规则适合做

- 日期、代码、单位、数据新鲜度和必填项检查；
- API 调用、重试、去重、缓存和数据库事务；
- Coverage、引用完整性和状态机；
- 未确认 Decision 不得写入等 Policy Gate。

### LLM 适合做

- 理解自然语言中的真实研究对象和关注点；
- 根据公司、行业、阶段与现有资料动态拆解问题；
- 阅读长文档并提出 Claim、冲突、反证和待验证项；
- 比较不同时间版本的变化；
- 在复盘中生成一个问题，而不是替用户完成归因。

### Agent 必须存在的原因

任务不是一次生成文本，而是一个多步、状态化、会失败的过程：先理解 → 看历史 → 规划 → 调工具 → 检查覆盖 → 缺什么补什么 → 综合 → 请求确认 → 写入 → 后续再恢复。固定 Prompt 无法可靠管理工具失败、证据缺口、跨轮状态和写入权限。

技术实现和 Skills 详见 Phase 3 文档。

## 9. 可信性与合规

- 每个关键数字必须带来源、日期、单位和口径；
- 搜索摘要只能做线索，形成事实前应打开原文；
- 模型记忆不能作为外部事实来源；
- 原文不可读时换来源，仍失败则明确显示“未核验”；
- 搜索轮数不是完成标准，Coverage 才是；
- 证据冲突不强行平均，保留双方来源与差异；
- 用户询问买卖/仓位时，只提供研究框架、风险和待验证项；
- Decision、Pattern、Rule 均设用户确认门；
- 研究报告展示信息边界，不伪装成投资建议。

## 10. 指标体系

### 北极星指标

**研究—决策—复盘闭环完成并在后续任务中成功复用历史判断的用户比例。**

### 第一层：任务价值

| 指标 | 说明 |
|---|---|
| 闭环完成率 | 发起研究后完成 Confirmed Decision 和 Reviewed 的比例 |
| 历史判断复用率 | 后续研究或复盘成功加载正确 Thesis 版本的比例 |
| 重复研究节省时间 | 同一对象第二次研究相对首次/手工流程的时间差 |

### 第二层：研究质量

| 指标 | 说明 |
|---|---|
| 必需项覆盖率 | 研究模板的关键问题有证据或明确缺口 |
| 数字可回查率 | 抽样数字能回到原文、日期、单位、口径 |
| 引用支持率 | Claim 的引用确实支持该 Claim |
| 失败透明率 | 数据/API 失败时没有静默产出正常结论 |

### 第三层：体验与安全

| 指标 | 说明 |
|---|---|
| 首次任务完成率 | 新用户无人工接管完成主链路 |
| 澄清有效率 | 澄清后研究路径确实改变，而非礼貌性追问 |
| 未授权写入数 | 未确认 Decision / Rule 的写入，目标为 0 |
| 直接荐股越界数 | 合规测试中的买卖指令，目标为 0 |

这些指标的目标值和实测结果将在测试报告中分开记录，尚未测试的不会预填。

## 11. 竞争与替代方案

| 方案 | 强项 | 缺口 |
|---|---|---|
| 行情终端 | 实时行情、公告、数据覆盖 | 不理解个人 Thesis，也不完成长期复盘 |
| 搜索/财经社区 | 快速获得多元线索 | 来源质量不一、难形成版本化判断 |
| 通用聊天模型 | 对话自然、分析灵活 | 默认缺少可靠市场工具、持久状态、写入门和金融 Coverage |
| Notion / Markdown | 自由记录、长期保存 | 不会主动检索、核验、比较和恢复上下文 |
| 自渡 | 研究与个人复盘闭环、证据和状态可回查 | 数据覆盖与稳定性仍弱于专业终端；需要用户持续参与 |

## 12. 产品边界与路线

### 本次必须做好

- 一个公开公司完整研究；
- 带来源和缺口的结构化档案；
- 一条匿名模拟 Decision；
- 一次基于事前版本的 Guided Review；
- 数据/模型失败时清楚降级。

### 后续再做

- 行业与事件的每日自动更新；
- 多用户账号、云同步与权限；
- 机构协作、审批和投研任务管理；
- 组合层归因与风险预算；
- 更多付费数据源和机构级一致预期。

## 13. 最终主张

自渡的创新不在于“让大模型写一篇更长的研报”，而在于把专业研究、个人判断、真实执行和复盘记忆放进同一条受约束的 Agent 工作流：事实可以回查，失败会暴露，关键判断由人确认，历史能够被下一轮继续使用。
