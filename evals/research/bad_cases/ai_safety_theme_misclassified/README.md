# Bad Case：AI 安全主题研究

## 用户问题

> 你分析一下最近一直强调的 AI 安全事件，从什么时候开始，为什么，到现在怎么样了

这不是一句模糊闲聊。用户已经给了三个明确分析维度：起点、升温原因、当前状态。投资研究还应补齐定义边界、产业传导、受益与承压环节、预期变化、里程碑和反证。

## 原始失败

最初系统把“AI 安全”建模成一件离散事件。Planner 虽然不断搜索，但没有稳定的主题边界和覆盖合同；最终只保留一篇二手材料，以 UNKNOWN 和“无法判断”为主要输出。公开 Trace 显示首轮只有 `1/12` 必需项完成。

## 根因与修复

1. 对象建模：增加 `EVOLVING_THEME`，区分长期主题与离散事件。
2. 研究框架：用 13 项证据合同覆盖定义、起源、时间线、催化、主体、传导、投资映射和反证。
3. 来源处理：允许与主题 Playbook 匹配的英文官方资料进入相关性判断与证据抽取。
4. 最终选择：按证据类别保留代表性 claim，避免公司财务排序规则误删主题证据。
5. Human-in-the-loop：只对没有研究边界的泛问句追问；已给出维度的问题直接执行。
6. 回归资产：把真实 Run/Trace 的失败、根因、修复与前后指标保存为可执行 Bad Case。
